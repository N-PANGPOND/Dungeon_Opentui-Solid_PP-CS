# สรุปการแก้ไขระบบ Event Splash Screen (แยกตามไฟล์)

สรุปแบบอ่านง่ายๆ สบายๆ ว่าแต่ละไฟล์แก้ตรงไหน และแก้ไปทำไม เพื่อให้ระบบแสดงภาพ Pixel Art ค้างไว้ 3 วินาทีเวลาก้าวไปเจอ Event ในดันเจี้ยนครับ

---

### 1. `Source-code/Type-Enum/type.ts`
* **แก้อะไร:**
  * เติม `"EVENT"` เข้าไปใน type `gameScreen`
* **แก้ทำไม:**
  * เพื่อให้ TypeScript รู้จักว่าตอนนี้เกมของเรามีสถานะหน้าจอเพิ่มขึ้นมาอีกหนึ่งหน้าชื่อว่า `"EVENT"` โค้ดส่วนอื่นๆ จะได้เรียกใช้ได้โดยไม่มี error แจ้งเตือน

---

### 2. `Source-code/Game/State.ts`
* **แก้อะไร:**
  * โหลดไฟล์ `event.json` (ข้อมูล Pixel Art) มารอไว้ตั้งแต่เริ่ม
  * เพิ่มตัวแปร `pendingEvent` เอาไว้เก็บข้อมูล (ชื่อ, สี, ตาราง pixel art) ของอีเวนต์ที่เพิ่งสุ่มเจอ
  * เพิ่มโค้ดในฟังก์ชันของอีเวนต์ต่างๆ (`eventTrap`, `eventTreasure`, `eventPotion`, `eventShop`, `eventCombat`) ให้บันทึกข้อมูลหน้าตา Pixel Art ลงใน `pendingEvent`
  * เพิ่มฟังก์ชัน `getPendingEvent()` ให้ UI มาหยิบข้อมูลไป และ `clearPendingEvent()` เพื่อล้างข้อมูลเมื่อโชว์ครบเวลา
* **แก้ทำไม:**
  * แยกหน้าที่ชัดเจน ให้ตัวเกมทำหน้าที่แค่บอกว่า *"ตอนนี้เจอเหตุการณ์นี้นะ นี่คือข้อมูลภาพ"* โดยเราจะไม่ใส่โค้ดหน่วงเวลา (`sleep` หรือ `setTimeout`) ในไฟล์นี้ เพื่อให้ตรรกะของเกมยังคงสะอาดและทำงานได้เร็วเหมือนเดิม

---

### 3. `Source-code/Tui/uiTypes.ts`
* **แก้อะไร:**
  * เติม `"EVENT"` เข้าไปใน `UIScreen`
  * สร้าง Type ใหม่ชื่อ `EventScreenUIProps` (มี `name`, `grid`, `color`)
* **แก้ทำไม:**
  * กำหนดโครงสร้างข้อมูลให้ฝั่งหน้าจอ (UI) รู้ว่าหน้าต่างอีเวนต์ต้องการข้อมูลอะไรบ้างในการนำไปวาดภาพบน Terminal

---

### 4. `Source-code/Tui/gameBridge.ts`
* **แก้อะไร:**
  * เพิ่มฟังก์ชัน `getEventScreenProps()` ให้อ่านค่า `pendingEvent` จากเกม
  * อัปเดต `resolveScreen()` ให้ตรวจว่า ถ้ามีอีเวนต์ค้างอยู่ (`pendingEvent !== null`) ให้บอก UI ทันทีว่าตอนนี้คือหน้า `"EVENT"`
* **แก้ทำไม:**
  * ไฟล์นี้ทำหน้าที่เป็นตัวกลาง (Bridge) คอยแปลภาษาจาก Game Logic ไปให้ UI การเช็คที่นี่ทำให้หน้า UI รู้ได้เองอัตโนมัติว่าตอนไหนต้องเปลี่ยนหน้า โดยที่ UI ไม่ต้องไปยุ่งกับตัวแปรลึกๆ ของเกม

---

### 5. `Source-code/Tui/components/CombatView.tsx` & `EventSplashScreen.tsx`
* **แก้อะไร:**
  * ปรับให้แสดงผลแบบพอดีใน **"ช่องแมพ"** (กว้าง 94 × สูง 29 ช่อง)
  * วาดภาพ Pixel Art (27 แถว × 46 คอลัมน์) จาก `event.json` โดยแปลงเลข `1` เป็น `"██"` และเลข `0` เป็นช่องว่าง `"  "`
  * ในหน้า `CombatView`: แสดง Pixel Art ของมอนสเตอร์ (Normal / Elite / Boss) พร้อมแถบ HP และ ATK/DEF ซ้อนอยู่ด้านบน และคำแนะนำปุ่มโจมตี/ป้องกันด้านล่าง
  * ในหน้า `EventSplashScreen`: แสดง Pixel Art ของ Trap / Treasure / Potion / Shop พร้อมเวลานับถอยหลัง 3 วินาที
* **แก้ทำไม:**
  * แทนที่การเปลี่ยนทั้งหน้าจอ การให้ภาพ Pixel Art แสดงแทนที่เฉพาะ **"ช่องแมพ" (MAP Box)** จะทำให้ส่วนอื่นๆ (แถบเลือด Player, ช่อง Inventory, ปุ่มกด Action, และ กล่องข้อความ Log) ยังคงแสดงผลอยู่เหมือนเดิม ไม่หายไปไหน

---

### 6. `Source-code/Tui/tui.tsx`
* **แก้อะไร:**
  * ปรับโครงสร้างเลย์เอาต์ให้ส่วน **ช่องซ้ายบน (MAP)** สลับการแสดงผลด้วย `<Switch>` ระหว่าง `DungeonView`, `EventSplashScreen`, และ `CombatView`
  * เมนูฝั่งขวา (Player / Inventory / Controls) และกล่อง Log ด้านล่างยังคงทำงานและมองเห็นได้ตลอดเวลา
  * จัดการเวลานับถอยหลัง 3 วินาทีสำหรับ Event ทั่วไป และบล็อกปุ่มเดินชั่วคราว
* **แก้ทำไม:**
  * ทำให้ผู้เล่นเห็นสถิติตัวละคร ไอเทม และ Log ต่อสู้ไปพร้อมๆ กับที่เห็นภาพกราฟิก Pixel Art ของมอนสเตอร์หรืออีเวนต์ในช่องแมพได้อย่างสมบูรณ์แบบ

---

### 🔄 สรุปภาพรวมการทำงาน
1. **เดินเจอ Event ทั่วไป (Trap / Treasure / Potion / Shop):**
   - ช่องแมพเปลี่ยนเป็นภาพ Pixel Art ของอีเวนต์นั้นๆ 3 วินาที
   - แถบเลือด/เหรียญของผู้เล่น และข้อความ Log อัปเดตทันที
   - ครบ 3 วินาที ช่องแมพจะตัดกลับเป็นแผนที่เดิมให้เดินต่อ
2. **เดินเจอมอนสเตอร์ (Combat):**
   - ช่องแมพเปลี่ยนเป็นภาพ Pixel Art ของมอนสเตอร์ทันที (พร้อมแถบ HP มอนสเตอร์)
   - แถบขวาล่างเปลี่ยนเป็นปุ่มต่อสู้ (1: Attack, 2: Strike, 3: Item, 4: Run)
   - ผู้เล่นสามารถสู้กับมอนสเตอร์ต่อได้ทันทีจนจบการต่อสู้ เมื่อชนะ/จบการต่อสู้ ช่องแมพจะตัดกลับเป็นแผนที่เดิม
